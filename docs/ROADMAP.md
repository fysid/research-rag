# План Research RAG

## Этап 1 — репозиторий

Результат: fork с историей, инструкциями для LLM, шаблонами задач/PR, владельцем кода и проверкой метаданных. Публикующие и служебные workflows ограничены upstream. Изменения проходят через PR.

Готовность подтверждается PR, результатом `Repository checks` и фактически применёнными настройками GitHub. Работа RAG на этом этапе не заявляется.

## Этап 2 — воспроизводимый локальный запуск

Перед реализацией зафиксировать ОС, RAM/VRAM, CPU/GPU, типы и объём документов. Выбрать локальный LLM, embedding-модель и векторное хранилище из поддерживаемых AnythingLLM вариантов.

- Проверить переход с upstream Node 18 на поддерживаемый runtime и воспроизводимые зависимости корня.
- Подготовить один документированный способ запуска из исходников или Docker.
- Проверить локальные провайдеры, telemetry и исходящие подключения; описать скачивания моделей.
- Определить локальные каталоги документов/индексов/БД и резервное копирование.
- Провести smoke test на синтетическом документе: загрузка → индексирование → вопрос → ответ с источником.

Готовность: запуск в чистом окружении по инструкции и проверенный ответ на контрольный вопрос. Полностью офлайн-режим заявлять только после проверки сети и наличия моделей.

## Этап 3 — исследовательские функции

Определить отличия от AnythingLLM по результатам локального запуска. Каждое изменение — отдельная задача с примерами и критериями. Не выбирать заранее новую RAG-архитектуру.

## Этап 4 — автоматизация LLM-разработки

По отдельному решению добавить запуск агента из GitHub Issues, ограничения прав/бюджета, независимое ревью и критерии качества. До этого агент работает по переданной задаче; CI не расходует платные LLM API.
