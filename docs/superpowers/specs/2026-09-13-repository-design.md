# Research RAG: подготовка репозитория

Объём следует первому этапу запроса владельца: GitHub-репозиторий на базе fork AnythingLLM, разработка через LLM. Fork создан как `fysid/research-rag`; видимость public, основная ветка `master`.

Архитектура приложения остаётся upstream. Дополняются инструкции агента, процесс Issue → branch → checks → review → PR, карта этапов, правила обновления upstream и исключения локальных данных из Git. Владелец принимает результаты; автоматический LLM-бот и платные API не подключаются.

Обычный fork сохраняет историю и upstream-связь. Приватная копия потребовала бы отдельного репозитория; отдельная оболочка добавила бы лишний проект. Используется уже созданный владельцем fork.

Изменения: AGENTS.md, вступления README/CONTRIBUTING, docs/LLM_DEVELOPMENT.md, docs/UPSTREAM.md, docs/ROADMAP.md, CODEOWNERS, шаблоны Issue/PR, .gitignore и CI. Upstream LICENSE сохраняется. Jobs публикации, cleanup и sponsors разрешены только исходному репозиторию. Repository checks проверяет файлы и whitespace; проверки приложения сохраняются.

GitHub: включить Issues и Actions после внесения workflow gates; требовать PR и зелёный Repository metadata для master, если доступно. Не требовать второго владельца для одного участника; не включать автоматическое слияние. Проверить настройки отдельно от файлов.

Критерии: fork подтверждён GitHub; изменения доступны в PR; YAML и ссылки проверены; Repository checks проходит; настройки подтверждены. Неприменённые настройки и неисполненные тесты отражаются в результате. Запуск RAG и выбор моделей относятся к следующему этапу.
